# 低耦合规则

本文件约束这个工作流如何保持通用，避免变成某个项目的专用脚本。

## 工作流只负责什么

```text
1. 找 GUI 根节点。
2. 导出指定 GUI 子树。
3. 解析快照。
4. 对比 before / after。
5. 输出 UI 读懂报告。
```

## 工作流不应该内置什么

```text
1. 不内置 ScreenGui 名字，例如 MainGui。
2. 不内置页面名，例如 MainPage、AttrPage。
3. 不内置面板名，例如 TaskPanel、KeyTipPanel。
4. 不内置某个项目的素材表路径。
5. 不内置某个项目的生成脚本路径。
```

## 项目差异放在哪里

项目差异必须作为参数或报告内容出现：

```text
1. TARGET_PATHS：由总览导出、用户说明、或项目文档决定。
2. Snapshot 文件名：由当前项目和当前改动决定。
3. 生成脚本路径：由当前项目结构决定。
4. 检查命令：由当前项目工具链决定。
```

## Codex 的默认行为

当用户只说“读一下这个项目 / 读一下这些文件”时：

```text
1. 不猜项目 GUI 名字。
2. 先读 WORKFLOW_MANIFEST.json。
3. 让用户运行总览导出器，或读取已有总览导出。
4. 从总览里选择候选 GUI 路径。
5. 再让用户运行聚焦导出器。
```

## 当前项目示例的边界

当前项目的路径、页面名、面板名可以出现在：

```text
1. 本次对话的操作说明。
2. 项目的 UI 读懂报告。
3. 项目自己的交接文档。
```

不能写成工作流的固定规则。
